# Frontend AI failures v0.6: backtest against the ten fielded interviews

Date: 13 November 2026. This is a local, privacy-preserving diagnostic of the
draft v0.6 guide and code. It did not contact participants or call a model with
their transcripts. Counts below are aggregate; no participant text or IDs are
retained in this report.

## Historical baseline

- Ten fielded v0.5 sessions: nine completed, one timed out, 238 participant turns.
- Seven firsthand in-scope frontend failures; two adjacent cases; one person
  reported no clear failure (manual coding in the fielding report).
- Seven of nine feedback respondents said questions repeated. Manual review
  found repeated context or constraint prompts in six interviews.
- Controller telemetry recorded six `answer_requirement_repair` events on the
  closing question, even though it merely asked for another possible task.
- Privacy telemetry recorded four link removals and three whole-answer
  `llm_direct_identifier` removals. The original text of the latter cannot be
  reconstructed from the stored transcripts.
- One participant asked whether a design-led case counted. The new scope
  matcher identifies that historical question.

## What the counterfactual checks showed

| Check | v0.5 | Final v0.6 draft |
| --- | ---: | ---: |
| Guide questions | 16 | 14 |
| Forced `always_ask` cards | 10 | 0 |
| Sum of per-card follow-up caps | 27 | 22 |
| Closing question treated as a fresh failure gate | Yes; six observed false repairs | No |
| Covered dependency still forces an earlier question | Yes for protected cards | No |

With the same simulated evidence ledger already covering task, inputs, AI
actions, requirements, observed failure, and desired result, the old guide's
next question was `candidate_tasks`; the revised guide's next question was
`detection`, the first missing topic. With every criterion marked covered, the
revised controller has no next question. This tests navigation, not whether
the evidence judge will correctly mark a real answer covered.

The first draft of v0.6 failed two backtest checks and was corrected before
this report: nine cards were still protected from skipping, and the opening
wording activated a strict failure gate. Only two of ten historical first
episode answers contained the gate's exact failure signal, so that gate could
have challenged eight ordinary task descriptions. The final opening accepts
the task description and probes the exact defect later. Explicit statements
that no failure comes to mind now end the interview without pressing for one.

For privacy, synthetic work examples containing a product/model name,
employer, URL, and breakpoint lost two links and an organization under the old
local filter; the work profile preserves all of those details. A separate
canary confirms that an email and API key are removed while the UI failure
remains. A specific person's severe health disclosure is removed at sentence
level while the separate UI failure sentence remains. This cannot recover or
reclassify the three answers already withheld in v0.5.

## Verification and limits

- 281 focused tests pass, including chat ingress, storage, export, no-failure
  completion, scope matching, dependency skipping, and privacy canaries.
- The existing event-by-event replay utility aligned zero of nine completed
  sessions: telemetry contains multiple controller events per visible agent
  turn and no sequence mapping. Its zero-decision result was **not** used as
  evidence of improvement.
- There has been no new participant run or model-generated v0.6 interview.
  Naturalness, actual repeat rate, and evidence yield remain unmeasured.
- The live study remains v0.5; v0.6 is a local draft.
